创建版本库
mkdir 目录名
cd 目录名   (切换，进入别的目录)
pwd(输出当前所在目录位置)
git it
find ~ -type d -name "Learngit"

把文件添加到版本库
git add文件名      添加文件到暂存区
git commit --m "add文件名“    一次性提交暂存区的所有修改

git status 显示仓库当前的状态
git diff 文件名   查看修改情况

版本回退
git log 显示提交日志
1.退回上一个版本    git reset --hard HEAD^     上上个版本HEAD^^       往上一百个版本  HEAD~100
--hard  退回上个版本已提交状态    --soft  退回上个版本未提交状态    --mixed退回上各个版本已添加但未提交状态
2.回到未来某个版本   git reset --hard 版本号
git reflog   记录每一次命令，确定未来版本的版本号

git 管理的是修改不是文件   不用git add添加到缓存区，那就不会加入到commit中

撤销修改
一.删除内容在工作区
git checkout -- 文件名   把文件在工作区的修改全部撤销
1.自修改后没有放入暂存区     改回和版本库一样的状态
2.已经添加到暂存区，又做了修改     改回到添加到暂存区的状态
二.铲除内容在暂存区
git reset HEAD 文件名      把暂存区的修改退回到工作区
再用 git checkout -- 文件名
三.删除内容在版本库
git reset --hard HEAD^

删除文件夹
rm 文件名    或 直接手动删
git rm 文件名     删掉文件同时把删除这个动作加到暂存区
git commit --"remove 文件名"
删错了一键恢复  git checkout --文件名

Git支持多种协议，默认的git://使用ssh，但也可以使用https等其他协议。
使用https除了速度慢以外，还有个最大的麻烦是每次推送都必须输入口令，但是在某些只开放http端口的公司内部就无法使用ssh协议而只能用https。

BUG分支
stash功能，可以把当前工作现场“储藏”起来，等以后恢复现场后继续工作：
git stash
首先确定要在哪个分支上修复bug，假定需要在main分支上修复，就从main创建临时分支
git checkout main
git checkout -b issue-101
修改bug后   git switch main
合并分支
git merge --no-ff -m "merged bug fix 101" issue-101
返回原分支
git switch dev
查看工作现场
git stash list
回到工作现场
git stash pop      恢复的同时把stash内容也删了
可以多次stash，恢复的时候，先用git stash list查看，然后恢复指定的stash
git stash apply stash@{0}
恢复后，stash内容并不删除，你需要用git stash drop来删除

在main分支上修复的bug，想要合并到当前dev分支，可以用git cherry-pick <commit>命令，把bug提交的修改“复制”到当前分支
