版本回退
git log 显示提交日志
1.退回上一个版本    git reset --hard HEAD^     上上个版本HEAD^^       往上一百个版本  HEAD~100
--hard  退回上个版本已提交状态    --soft  退回上个版本未提交状态    --mixed退回上各个版本已添加但未提交状态
2.回到未来某个版本   git reset --hard 版本号
git reflog   记录每一次命令，确定未来版本的版本号

撤销修改
一.删除内容在工作区
git checkout -- 文件名   把文件在工作区的修改全部撤销
1.自修改后没有放入暂存区     改回和版本库一样的状态
2.已经添加到暂存区，又做了修改     改回到添加到暂存区的状态
二.铲除内容在暂存区
git reset HEAD 文件名      把暂存区的修改退回到工作区
再用 git checkout -- 文件名
三.删除内容在版本库
git reset --hard HEAD^

BUG分支
stash功能，可以把当前工作现场“储藏”起来，等以后恢复现场后继续工作：
git stash
首先确定要在哪个分支上修复bug，假定需要在main分支上修复，就从main创建临时分支
git checkout main
git checkout -b issue-101
修改bug后   git switch main
合并分支
git merge --no-ff -m "merged bug fix 101" issue-101
返回原分支
git switch dev
查看工作现场
git stash list
回到工作现场
git stash pop      恢复的同时把stash内容也删了
可以多次stash，恢复的时候，先用git stash list查看，然后恢复指定的stash
git stash apply stash@{0}
恢复后，stash内容并不删除，你需要用git stash drop来删除

在main分支上修复的bug，想要合并到当前dev分支，可以用git cherry-pick <commit>命令，把bug提交的修改“复制”到当前分支

多人协作
查看远程库信息
git remote
git remote -v
推送分支
推送分支，就是把该分支上的所有本地提交推送到远程库。推送时，要指定本地分支，这样，Git就会把该分支推送到远程库对应的远程分支上
git push origin main 
创建远程origin的dev分支到本地
git checkout -b dev origin/dev
多人协作的工作模式：
首先，可以尝试用git push origin <branch-name>推送自己的修改
如果推送失败，则因为远程分支比你的本地更新，需要先用git pull把最新的提交从origin/dev抓下来，试图合并
如果合并有冲突，则解决冲突，并在本地提交
没有冲突或者解决掉冲突后，再用git push origin <branch-name>推送就能成功
如果git pull提示no tracking information，则说明本地分支和远程分支的链接关系没有创建，用命令git branch --set-upstream-to <branch-name> origin/<branch-name>

rebase
rebase的目的是使得我们在查看历史提交的变化时更容易，因为分叉的提交需要三方对比。
git rebase把分叉的提交历史“整理”成一条直线，看上去更直观。缺点是本地的分叉提交已经被修改过了

tag 
tag就是一个让人容易记住的有意义的名字，它跟某个commit绑在一起

创建标签
git checkout  分支   切换到需要打标签的分支
git tag 名字
git tag -a  名字 -m "说明文字"
git tag  查看所有标签
git show 名字   查看标签信息 可以看到说明文字
默认标签是打在最新提交的commit上的。有时候，如果忘了打标签，方法是找到历史提交的commit id
git log
git tag 名字  版本号
git tag -a  名字  -m "说明文字“  版本号  
标签总是和某个commit挂钩。如果这个commit既出现在main分支，又出现在dev分支，那么在这两个分支上都可以看到这个标签。

操作标签
删除标签
本地
git tag -d 名字
远程
git tag -d 名字
git push origin :refs/tags/名字
推送某个标签到远程  
 git push oringin <tagname>
一次性推送全部尚未推送到远程的本地标签    
git push origin --tags
